## 2. Audit konsistensi R3

Audit dilakukan satu pass terhadap rev3 dan seluruh dokumen P1.1–P1.8:

| Pemeriksaan | Hasil | Temuan/perbaikan |
|---|---|---|
| Setiap tabel ERD terdaftar di kamus data | **LULUS** | `DATA_DICTIONARY_FINAL.md` memuat seluruh tabel legacy dari ERD dan seluruh tabel baru yang digambar; matriks inventaris eksplisit. |
| Setiap kolom baru memiliki tipe, nullable dan default | **LULUS** | Field-level dictionary menulis ketiganya; aturan “tanpa default” dibedakan dari `NULL DEFAULT NULL`. |
| Istilah/status/enum konsisten | **LULUS** | PO, reservation, quality, return, channel, trading, snapshot, recommendation dan unit-verification dinormalisasi pada satu tabel status. Legacy `VARCHAR` dibedakan dari constraint yang baru diusulkan. |
| Idempotency: key sama + payload sama dan berbeda | **LULUS** | Kontrak global: payload sama mengembalikan hasil sebelumnya; payload berbeda ditolak. `IDEM-01..14` menguji tiap operasi idempoten yang dirancang. |
| Nomor aturan asli Bagian 7 | **LULUS** | Semua heading dan butir Handover rev3 7.1–7.11 memiliki trace row dan test ID; tidak ada butir tanpa test case yang direncanakan. Tes belum dijalankan. |

## 3. Konflik dan resolusi

| ID | Konflik | Resolusi |
|---|---|---|
| C1 | Low-stock P1.2 vs P1.6 dan query dashboard | Query legacy memang membandingkan `remaining-reserved` raw dengan `minimum_stock`. Pertahankan query lama dengan badge unverified; jangan klaim base/Q. |
| C2 | Presisi quantity/factor/cost | Quantity `DECIMAL(15,3)` dan scale 0–3; factor `DECIMAL(18,9)`; cost/base `DECIMAL(20,8)`. Nilai yang tidak representable ditolak. |
| C3 | Saldo `legacy_unverified` vs gerbang P1.1/P1.3 | Saldo mentah hanya kompatibilitas/rekonsiliasi; bukan base demand/Q/receipt. Verifikasi per produk lalu konversi auditable sebelum flag baru. |
| C4 | Product unit vs product-supplier configuration | `product_unit_conversions` untuk product–unit; `product_suppliers` menyimpan purchase unit/F/M/U/lead-time dan snapshot transaksi. |
| C5 | PO legacy `ordered` vs status lifecycle baru | Lifecycle baru draft→sent→confirmed→partially_received→received/cancelled; legacy `legacy_open_review`/`legacy_review` tidak masuk IP/Q. |
| C6 | Idempotency pada beberapa event | Unique key scoped per operasi/parent; payload sama replay-safe, payload berbeda ditolak; IDEM-01..14 memetakan setiap operasi. |
| C7 | DATETIME dan tanggal historis demo | BusinessClock Asia/Jakarta; timezone app/DB eksplisit; jangan mengubah interpretasi legacy. |
| C8 | Kuota klaim retur vs pengurangan demand | `eligible_qty`, accepted returns, active claim dan claimable-now terpisah; demand hanya accepted physical return. |
| C9 | COGS aktual vs estimasi procurement | COGS aktual dari cost snapshot batch; Q estimate dari PO item terakhir lalu batch terakhir dengan label estimasi. |
| C10 | Cardinality prescription–order | FK `prescriptions.order_id` non-unique memberi 1:N secara fisik. Default desain tetap 1:N; **keputusan bisnis pengguna masih ditunggu** sebelum penambahan constraint/aturan workflow. |
| C11 | ERD/kamus lama | `orders.address_snapshot` LONGTEXT; `shipments.order_id` unique; status live VARCHAR bebas. Dictionary diperbaiki berdasar metadata. |
| C12 | CI3 `migrations` vs checksum | Satu registry `schema_migrations`, CLI; native auto migration tetap nonaktif. |
| C13 | Akun DB | Temuan root/password kosong ditutup sebagai gate Phase 0b; tidak dibuat/diubah sekarang. |
| C14 | Reset demo | Wajib DB suffix `_demo` DAN `environment_marker=demo`; fail closed jika salah satu tidak cocok. |
| C15 | Generator | Tunggu BusinessClock dan domain service P1.2–P1.6; tidak boleh raw INSERT yang bypass invariant. |

## 5. Risk register

| Risiko | Kontrol |
|---|---|
| Privilege DB/default credential berlebih | 0b least privilege, grants negative tests, no cross-access. |
| Konversi saldo/unit legacy salah | Legacy tetap unverified, audit per product, before/after reconciliation. |
| Migrasi/reset rusak atau parsial | Encrypted verified backup, lint, checksum, lock, dry-run, scratch restore. |
| Race payment/receipt/return/draft PO | Transaction/locking, scoped idempotency, same/different-payload tests. |
| Timezone/history salah | BusinessClock Asia/Jakarta, boundary tests, immutable snapshots. |
